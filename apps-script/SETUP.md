# Apps Script 백엔드 배포 가이드 (운영자용, 1회)

이 문서는 **운영자(사이트를 실제로 굴리는 사람)** 가 딱 한 번 수행하는 절차다. 교사는 이 과정을 몰라도 된다 — 배포된 URL을 사이트가 대신 호출해줄 뿐이다. (전체 구조는 `docs/PLAN.md`의 아키텍처 절 참고)

## 무엇이 만들어지는가

배포하면 **운영자의 Google Drive**에 아래가 생긴다.

```
내 드라이브/
└─ InteractiveClass/
   ├─ _index                (수업 코드 ↔ editToken 해시 ↔ 응답 시트 ID 매핑)
   ├─ lessons/<CODE>.json    각 수업의 전체 내용
   ├─ media/<CODE>/...       교사가 올린 이미지
   ├─ uploads/<CODE>/...     학생이 올린 사진·그림
   └─ responses/
      └─ 응답 - <CODE>       수업마다 하나씩 생기는 응답 스프레드시트
```

**중요**: 이후 모든 교사·학생의 데이터가 **이 계정**에 쌓인다. 학교 공용 계정이든 개인 계정이든, 이 계정을 계속 쓸 수 있는 계정으로 정할 것 — 나중에 계정을 바꾸면 기존 수업 코드가 전부 무효가 된다.

## 1. Apps Script 프로젝트 만들기

1. [script.google.com](https://script.google.com) 접속 → **새 프로젝트**
2. 프로젝트 이름을 "InteractiveClass Backend" 등으로 바꾼다 (좌상단 제목 클릭)

## 2. 코드 붙여넣기

1. 왼쪽 파일 목록의 `Code.gs`를 열고, 안의 내용을 전부 지운 뒤 이 저장소의 **`apps-script/Code.gs`** 내용을 그대로 붙여넣는다.
2. 왼쪽 파일 목록 옆 **⚙️(프로젝트 설정)** → **"appsscript.json" 매니페스트 파일을 편집기에서 보기** 체크박스를 켠다.
3. 파일 목록에 나타난 `appsscript.json`을 열고, 이 저장소의 **`apps-script/appsscript.json`** 내용으로 통째로 바꾼다.
4. 저장 (Ctrl+S 또는 💾 아이콘).

## 3. 웹앱으로 배포

1. 우상단 **배포(Deploy) → 새 배포(New deployment)**
2. 유형 선택(⚙️) → **웹 앱(Web app)**
3. 설정:
   - **설명**: 아무거나 (예: "v1")
   - **다음 계정으로 실행**: **나 (Me)** — 반드시 이걸 선택해야 학생이 로그인 없이 써도 운영자 계정의 Drive에 저장된다.
   - **액세스 권한이 있는 사용자**: **모든 사용자(Anyone)** — 학생이 로그인 없이 접근해야 하므로.
4. **배포** 클릭.
5. 처음 배포하면 "권한 검토" 화면이 뜬다. **본인 계정 선택 → 고급(Advanced) → InteractiveClass Backend(안전하지 않음)로 이동 → 허용.**
   - "안전하지 않음"이라고 나오는 건 이 스크립트가 Google의 공식 심사를 받지 않은 개인 프로젝트라서 뜨는 표준 경고다. 본인이 방금 작성한 코드이므로 허용해도 된다.
   - 요청하는 권한: **Drive**(수업·응답 저장), **스프레드시트**(응답 시트). 이 두 개 외에 다른 권한을 요구하면 코드를 다시 확인할 것.
6. 배포가 끝나면 **웹 앱 URL**이 나온다. `https://script.google.com/macros/s/AKfycb.../exec` 형태다. **이 URL을 복사해둔다.**

## 3-1. 관리자 비밀번호 등록 (전체 수업 관리 화면용)

사이트의 `/#/admin`(전체 수업 목록·삭제·다운로드) 화면은 editToken이 아니라 **운영자 비밀번호 하나**로 보호된다. 이 비밀번호는 코드에 커밋하지 않고, Apps Script 프로젝트의 **스크립트 속성**에만 저장한다.

1. script.google.com 프로젝트 좌측 **⚙️(프로젝트 설정)** 클릭
2. 맨 아래 **스크립트 속성(Script properties)** → **스크립트 속성 추가**
3. 속성: `ADMIN_PASSWORD`, 값: 원하는 비밀번호 (충분히 긴 문자열 권장)
4. 저장. 코드를 다시 배포할 필요는 없다 — 스크립트 속성은 배포와 별개로 즉시 적용된다.

이 값을 설정하지 않으면 `/#/admin`은 항상 "관리자 비밀번호가 서버에 설정되어 있지 않습니다" 오류를 반환한다(의도된 동작 — 비밀번호 없이는 열리지 않는다).

## 4. 프런트엔드에 연결

프로젝트 루트에 `.env.local` 파일을 만들고(이미 있다면 열어서):

```
VITE_API_MODE=live
VITE_APPS_SCRIPT_URL=여기에_방금_복사한_exec_URL
```

`npm run dev`(로컬) 또는 실제 배포 빌드에 이 값이 반영되면 목 백엔드 대신 방금 배포한 실제 백엔드를 쓰게 된다. `docs/OPERATIONS.md`에도 이 URL을 기록해둔다(비밀값이 아니다 — editToken 없이는 아무것도 할 수 없는 공개 엔드포인트이기 때문).

## 5. 확인해보기

0. (선택) 배포된 URL을 **브라우저 주소창에 직접 붙여넣어** 열어본다. `{"ok":true,"data":{"status":"InteractiveClass 백엔드가 정상 동작 중입니다."}}` 같은 텍스트가 보이면 배포 자체는 정상이다.
1. 사이트에서 새 수업을 하나 만들어본다.
2. 본인 Google Drive를 열어 `InteractiveClass` 폴더가 생겼는지 확인한다.
3. 수업을 발행하고, 시크릿 창에서 학생으로 참여해 답을 하나 제출해본다.
4. Drive의 `InteractiveClass/responses/응답 - <코드>` 스프레드시트를 열어 응답 행이 생겼는지 확인한다.

## 코드를 고친 뒤 다시 배포하기

`Code.gs`를 수정했다면:

1. script.google.com 프로젝트를 다시 열어 수정된 내용을 붙여넣고 저장한다.
2. **배포 → 배포 관리(Manage deployments)** → 기존 배포 옆 연필(✏️) 아이콘 → 버전을 **새 버전(New version)** 으로 바꾸고 **배포**.
   - ⚠️ **"새 배포"를 또 만들면 URL이 바뀐다.** 반드시 **기존 배포를 편집**해서 새 버전으로 올려야 `.env.local`의 URL을 안 바꿔도 된다.

## 장애·한도 관련 참고

- Apps Script는 **하루 실행 시간·Drive 쓰기 횟수에 할당량**이 있다(개인 계정 기준 일일 실행시간 약 6시간, URL Fetch/Drive 호출 수 제한 등). 학생 수가 아주 많은 학교 전체 단위로 쓰기엔 부족할 수 있다 — 사용량이 늘면 이 부분을 다시 점검할 것.
- **동시 제출**은 `LockService`로 순서를 강제하므로 응답이 씹히지 않지만, 대기시간이 늘어날 수 있다(기본 최대 20초 대기 후 실패).
- 이 배포는 **테스트되지 않았다** — Google 계정 로그인·OAuth 동의가 필요한 절차라 자동화 도구가 대신 수행하지 않았다(운영자 본인 확인이 필요한 단계이기 때문). 위 "확인해보기" 절차를 반드시 직접 수행해서 정상 동작을 확인할 것. 문제가 생기면 `docs/OPERATIONS.md`의 장애 대응 절을 참고하거나, Code.gs 실행 로그(script.google.com → 왼쪽 "실행" 메뉴)를 확인한다.
