## 2026-07-30 URL 임베드 — 화이트리스트 유지 + HTML 업로드는 `srcdoc`

**결정**: 임베드 허용 도메인은 계속 화이트리스트(`embedHosts.ts`). 교사가 만든 HTML 업로드는
Drive에 저장하지 않고 **원문을 수업 JSON에 담아 `<iframe srcDoc>`으로 렌더링**한다(서버 왕복 없음).
sandbox는 링크 모드는 기존 권한 유지, 업로드 모드는 `allow-scripts`만.

**이유**: 임의 사이트를 iframe에 넣는 건 클릭재킹·피싱의 표준 공격 표면이다. 대부분 사이트가

**`srcdoc`에 도달한 경위(두 번의 실배포 실패)**: 처음엔 이미지처럼 Drive 저장 → URL 서빙을
따라가려 했다. 이 앱은 API가 전부 `doPost`라 GET을 못 받아 `doGet` 라우트를 새로 만들었는데,
① `ContentService`는 `MimeType.HTML`을 줘도 실제 Content-Type이 **`text/plain`**으로 나갔고,
② `HtmlService`는 Content-Type은 맞지만 Apps Script가 **자체 UI로 감싼다**(아이콘 스타일시트·
"악용 신고" 링크·이중 iframe 부트스트랩). 둘 다 근본은 같다 — **GET으로 원본 바이트를 그대로
돌려주는 것 자체가 Apps Script 웹앱 계층에서 신뢰할 수 없다.** 업로드가 이미 3MB 제한이라
JSON에 직접 담으면 이 문제 전체가 사라진다.

**버린 대안**: *화이트리스트 없애기* — 대상 사이트 정책 때문에 기능적 이득도 작은데 방어선만 없어진다.
*zip으로 여러 파일 지원* — 압축 해제 + 상대경로 리라이팅이 필요. "여러 파일이면 CodePen·Glitch에
올리고 링크 모드를 쓰라"로 안내.

## 2026-08-06 다크모드 — 토큰을 우회한 색을 없애고, 저자 지정 색은 토큰으로 저장

**결정**: "다크모드에서 일부 글자가 안 보인다" 신고를 받고 다섯 갈래로 고쳤다.

1. **뒤집히는 배경 + 안 뒤집히는 글자** — `bg-neutral-800/900` 위의 `text-white`를
   **`text-neutral-0`**으로 교체(Toast, 사진 삭제 칩, 참고자료 FAB, 잠긴 "다음" 버튼).
2. **강조색 글자** — 어두운 배경에서 대비 2.97까지 떨어졌다. accent-500/600은 **버튼 배경**으로도
   쓰여 뒤집을 수 없으므로 글자 전용 토큰 **`--color-accent-ink`**(라이트 #1d4ed8 / 다크 #93c5fd)를
   새로 만들었다.
3. **교사가 리치텍스트에서 고른 색**(신고의 주원인) — 색이 `style="color:#18181b"`처럼 **값 그대로**
   수업 JSON에 저장돼 검은 배경 위 검은 글자가 됐다. 팔레트를 전부 토큰으로 바꿔 **앞으로 저장되는
   값은 뒤집히게** 했고, **이미 저장된 옛 수업**은 렌더링 시점에 `lib/richTextColor.ts` 규칙으로
   갈아 끼운다(무채색이면서 아주 어둡거나 밝은 색만 — 유채색은 저자 의도라 그대로).
4. **형광펜** — 배경은 인라인 파스텔인데 글자는 본문에서 상속돼 흰색이 됐다. 종이 형광펜처럼
   "밝은 바탕 + 어두운 글자"로 고정(`mark, mark * { color:#18181b !important }` — `mark *`와
   `!important` 둘 다 필요하다).
5. **CSS로 색을 못 바꾸는 것** — 그리기 판을 **항상 흰 종이**로 고정.

부수적으로 주기율표가 밝은 분류색 위에 흰 글자를 써서 2.17:1이었다 — 배경 휘도로 검정/흰색을
고르게 바꿔 최소 4.95:1이 되게 했다.

**이유**: 다크모드 구조 자체는 잘 서 있었고 깨진 곳은 전부 **토큰을 우회한 색**이었다. 그래서
개별 화면을 땜질하는 대신 "우회로를 없애고, 없앨 수 없는 것(저장된 값)은 렌더링 시점에 되돌린다"로
갔다. 저자 지정 색은 **저장 형식을 토큰으로 바꾸는 것**이 유일한 근본 해결이다.

**버린 대안**: *accent 토큰 자체를 뒤집기* — 버튼이 밝은 파랑에 흰 글자가 되어 더 나빠진다.

**결정**: 응답 행을 `studentKey`로 먼저 찾고, 못 찾으면 **다듬은 학년·반·번호·이름**

안 생기게 해야지"). *서버가 열쇠를 다시 계산해 덮어쓰기* — 그 학생의 다른 기기가 든 열쇠와

## 2026-10-13 수업 중 채점을 학생 기기로 옮긴다 (정답을 내려보낸다)

**결정**: 학생용 `getLesson`이 정답·해설을 **빼지 않고** 내려주고, 플레이어가 `lib/grade.ts`로
그 자리에서 채점한다. 제출 때는 서버(`submitResponse`)가 지금처럼 다시 채점해 시트에 남긴다.
서버의 `gradeAnswer`·`gradeAnswers`는 옛 화면을 연 학생을 위해 남겨 두었다(지금 프런트는 안 부른다).

**이유**: 사용자 지시 — "모든 경우 정답을 기기로 보내 그 자리에서 채점. 수행평가같은 성적 반영할
내용이 아니기 때문에 괜찮다." 채점 한 번이 Apps Script 왕복(바닥값 1.2초, 수업 캐시가 만료되면
4~5초)이라 「넘길 때 공개」·분기 슬라이드에서 「다음」이 그만큼 멈췄다. 횟수를 줄이는 최적화(08-20)로는
바닥값을 못 넘는다. 기기 채점 뒤 공개까지 실측 **5ms**.

**함께 따라온 것**: 예전에는 학생 화면에 **해설이 한 번도 안 나왔다** — 해설까지 지워서 내려보냈기
때문이다. 이제 정오답 공개 시점에 해설이 같이 보인다.

**버린 대안**: *서버 채점 유지 + 답을 고르면 뒤에서 미리 채점* — 정답은 지키지만 서버 호출이 오히려
늘고, 답을 고치자마자 「다음」을 누르면 여전히 기다린다. *공개되는 문항만 정답을 내려보낸다* — 사용자가
「모든 경우」로 정했다.

**되돌리는 법**: `getLesson`에서 `stripAnswers(lesson)`을 다시 반환하고, `createLiveAdapter`의 채점을
`api.gradeAnswer(s)`로 돌린다(커밋 이력에 그대로 있다). **둘 중 하나만 되돌리면 전부 오답이 된다.**
